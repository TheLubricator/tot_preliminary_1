================================================================================
1. OVERVIEW: WHAT THE SYSTEM DOES
================================================================================

The system solves Game 24 puzzles using a hybrid approach that combines:
  • Breadth-First Search (BFS) with beam search
  • LLM (Large Language Model) evaluation for state assessment
  • Safe code execution sandboxing
  • Dead-end memory tracking for efficiency
  • Structured logging and tree export

INPUT: Four numbers (e.g., [1, 5, 9, 13])
OUTPUT: Sequence of operations reaching 24 (or "no solution found")
CONSTRAINT: Each operation combines 2 numbers into 1, reducing the set by 1 element


================================================================================
2. CORE CLASSES AND THEIR RESPONSIBILITIES
================================================================================

┌─ CLASS 1: SafeAgentSandbox
│  ├─ Purpose: Execute arbitrary Python code in a safe, isolated environment
│  ├─ Key Methods:
│  │  └─ run(code: str) → (output: str, new_state: list)
│  │     • Executes code with restricted globals
│  │     • Validates state transitions (n → n-1 numbers)
│  │     • Captures stdout and detects errors
│  │     • Returns both output text and resulting state
│  │
│  ├─ Safety Features:
│  │  • Restricted built-ins (no file access, no imports)
│  │  • Resource limits
│  │  • Error handling with meaningful feedback
│  │
│  └─ Example:
│     Input:  "res = numbers[0] + numbers[1]; new_numbers = [res] + remaining"
│     Output: "[6, 4]" (combined state)

├─ CLASS 2: TreeNode
│  ├─ Purpose: Represent a single state in the search tree
│  ├─ Key Attributes:
│  │  ├─ state: list        (e.g., [1, 5, 9, 13], [6, 4], [24])
│  │  ├─ parent: TreeNode   (link to parent state)
│  │  ├─ children: dict     (links to child states)
│  │  ├─ depth: int         (distance from root)
│  │  ├─ value: float       (LLM evaluation score 0.0-1.0)
│  │  ├─ is_solution: bool  (True if state == [24])
│  │  └─ path_history: str  (full trace from root to this node)
│  │
│  ├─ Key Methods:
│  │  ├─ to_dict() → dict
│  │  │  └─ Serializes node to JSON-compatible dictionary
│  │  │
│  │  └─ __init__(state, parent, action, depth)
│  │     └─ Creates new node with automatic ID assignment
│  │
│  └─ Data Flow:
│     TreeNode tracks: {thought, code, observation, evaluation}
│     These 4 fields form the reasoning chain from root to solution

├─ CLASS 3: DeadEndMemory [NEW]
│  ├─ Purpose: Learn from failed states and skip similar ones
│  ├─ Key Methods:
│  │  ├─ record_dead_end(node, reason)
│  │  │  └─ Extracts pattern (max_value, sum, structure) and stores
│  │  │
│  │  └─ is_potential_dead_end(state) → (bool, pattern_match)
│  │     └─ Checks if state matches known dead-end patterns
│  │
│  ├─ Memory Pattern Example:
│  │  IF (node.state has max_value > 50) AND (all values are single digits)
│  │     THEN likely dead-end (too hard to reduce to 24)
|  |     Note: can be configured if its deemed too greedy        
│  │
│  ├─ Efficiency Impact:
│  │  • Typical skip rate: 10-15%
│  │  • API calls saved per puzzle: ~5-12 calls
│  │
│  └─ Data Structure:
│     patterns = [
│       {
│         'state_structure': [...],
│         'max_value': 40,
│         'reason': 'values_too_large',
│         'found_at_depth': 2
│       },
│       ...
│     ]
|
├─ CLASS 4: InconsistencyDetector (Quality Assurance)  [NEW]
│  ├─ Purpose: Track LLM evaluation inconsistencies and flag unreliable states
│  ├─ Key Methods:
│  │  ├─ record_evaluation(state, score, depth, reasoning)
│  │  │  └─ Stores evaluation record for a state
│  │  │  └─ Tracks multiple evaluations of same state
│  │  │
│  │  ├─ is_inconsistent(state) → bool
│  │  │   └─ Returns TRUE if score variance > inconsistency_threshold (0.3)
│  │  │
│  │  ├─ get_inconsistent_states() → list
│  │  │   └─ Returns all states with conflicting evaluations
│  │  │
│  │  └─ get_stats() → dict
│  │     └─ Returns evaluation statistics
│  │
│  ├─ Inconsistency Example:
│  │  State: [5, 6, 7]
│  │  Evaluation 1: score=1.0 ("sure")
│  │  Evaluation 2: score=0.6 ("likely")
│  │  Evaluation 3: score=0.001 ("impossible")
│  │  Variance: 1.0 - 0.001 = 0.999 > 0.3 threshold
│  │  Status: FLAGGED AS INCONSISTENT ⚠️
│  │
│  ├─ Quality Control Impact:
│  │  • Tracks re-evaluation rate
│  │  • Identifies unreliable LLM responses
│  │  • Flags suspicious states for manual review
│  │  • Helps improve prompt quality
│  │
│  └─ Data Structure:
│     {
│       'state': [5, 6, 7],
│       'evaluations': [1.0, 0.6, 0.001],
│       'variance': 0.999,
│       'is_inconsistent': true
│     }

└─ CLASS 5: Game24TreeOfThoughts (Main Solver)
   ├─ Purpose: Orchestrate the entire search algorithm
   │
   ├─ Key Initialization Parameters:
   │  ├─ temperature: 0.7              (LLM randomness: 0=deterministic, 1=random)
   │  ├─ n_evaluate_sample: 3          (number of LLM evaluations per state)
   │  ├─ n_select_sample: 5            (beam width: keep top-5 nodes per depth)
   │  ├─ max_steps: 6                  (max search depth)
   │  ├─ enable_deadend_memory: true   (enable optimization)
   │
   ├─ Key Methods (in execution order):
   │
   │  1️⃣  propose(state, n_proposals=5)
   │      ├─ Input:  Current state (e.g., [6, 4])
   │      ├─ Process:
   │      │   • Construct LLM prompt with state and target (24)
   │      │   • Query Gemini API for multiple proposals
   │      │   • Extract thought + code + observation for each
   │      │   • Validate code execution via SafeAgentSandbox
   │      │   • Deduplicate results
   │      │
   │      └─ Output: 5 proposals as dicts with:
   │         {
   │           'thought': "Add 5 and 1",
   │           'code': "res = 5 + 1; ...",
   │           'observation': "[6, 4]",
   │           'new_state': [6, 4]
   │         }
   │
   │  2️⃣  evaluate_state(state, is_final=False)
   │      ├─ Input:  Current state (e.g., [6, 4])
   │      ├─ Process: THREE DIFFERENT EVALUATION MODES
   │      │
   │      │   ┌─────────────────────────────────────────────┐
   │      │   │ DEPTH 3: SINGLE NUMBER (FINAL ANSWER)      │
   │      │   └─────────────────────────────────────────────┘
   │      │   IF len(state) == 1:
   │      │      IF state[0] ≈ 24:
   │      │         └─ Return value=1.0 ✓ (SOLUTION FOUND!)
   │      │      ELSE:
   │      │         └─ Return value=0.001 (WRONG ANSWER)
   │      │          
   │      │   ┌─────────────────────────────────────────────┐
   │      │   │ HEURISTIC 1: PREMATURE 24 CHECK            │
   │      │   └─────────────────────────────────────────────┘
   │      │   IF 24 in state (but state length > 1):
   │      │      └─ Return value=0.01 ⚠️ (DEAD-END TRAP!)
   │      │      └─ Reason: Having 24 when other numbers exist
   │      │         prevents further useful operations
   │      │          
   │      │   ┌─────────────────────────────────────────────┐
   │      │   │ HEURISTIC 2: HUGE NUMBERS CHECK             │
   │      │   └─────────────────────────────────────────────┘
   │      │   IF max(abs(state)) > 1000:
   │      │      └─ Return value=0.1 ⚠️ (INTRACTABLE)
   │      │      └─ Reason: Numbers too large make reducing
   │      │         to 24 mathematically unlikely
   │      │
   │      │   ┌─────────────────────────────────────────────┐
   │      │   │ DEPTH 2: TWO NUMBERS (HARDCODED CHECK)    │
   │      │   └─────────────────────────────────────────────┘
   │      │   ELIF len(state) == 2:
   │      │      a, b = state[0], state[1]
   │      │      Check ALL 6 POSSIBLE OPERATIONS:
   │      │        • a + b = 24?  
   │      │        • a - b = 24?
   │      │        • b - a = 24?
   │      │        • a * b = 24?
   │      │        • a / b = 24? (if b ≠ 0)
   │      │        • b / a = 24? (if a ≠ 0)
   │      │      
   │      │      IF any operation reaches 24:
   │      │         └─ Return value=1.0 ✓ (SOLVABLE!)
   │      │      ELSE:
   │      │         └─ Return value=0.001 (IMPOSSIBLE!)
   │      │
   │      │   ┌─────────────────────────────────────────────┐
   │      │   │ DEPTHS 1+: THREE+ NUMBERS (LLM VOTING)     │
   │      │   └─────────────────────────────────────────────┘
   │      │   ELSE (3+ numbers):
   │      │      • Run VALUE_PROMPT_CODEACT n_evaluate_sample times (3x)
   │      │      • Collect LLM judgments: "sure", "likely", "impossible"
   │      │      • Tally votes: sure→1.0, likely→0.6, impossible→0.001
   │      │      • Average scores: (1.0+1.0+0.6)/3 = 0.867
   │      │      • Optional boost: ×1.2 if state has mixed magnitude
   │      │        (big numbers 20-40 mixed with small 1-10)
   │      │
   │      └─ Output: (value: float, eval_record: dict)
   │
   │  3️⃣  solve(numbers, verbose=True)
   │      ├─ Input:  List of 4 numbers (e.g., [1, 5, 9, 13])
   │      │
   │      ├─ Optional Mode: HYBRID SER (Selective Exhaustive Rescue)
   │      │  ├─ Enabled by: enable_ser=True
   │      │  ├─ Purpose: Fallback when LLM proposals are weak
   │      │  ├─ Strategy at Depth 0:
   │      │  │   • Generate ALL ~24 possible exhaustive first moves
   │      │  │   • Evaluate promising moves with LLM (top 3)
   │      │  │   • Score remaining moves with heuristics
   │      │  │   • Select best from both pools (mix LLM + heuristic) within n select range
   │      │  ├─ Benefit: due to enumeration and basic checks
            , more likely to find solutions when problem requires one mandatory operation
   │      │  └─ Trade-off: eliminates LLM proposal step, hence risk of losing ultimate goal of showing LLM lookahead 
                    capability, even though LLM evaluation is still present
   │      │
   │      ├─ Main Loop: for depth in range(max_steps):
   │      │
   │      │  BFS WITH BEAM SEARCH:
   │      │  ────────────────────
   │      │  Depth 0:
   │      │    queue = [root_node]
   │      │    for node in queue:
   │      │        proposals = propose(node.state)        ← 5 proposals
   │      │        create child nodes for each proposal
   │      │        add to next_queue
   │      │    [next_queue has ~5 nodes created]
   │      │    evaluate_state() for each child
   │      │    sort next_queue by value (descending)     ← GLOBAL SORT
   │      │    selected = next_queue[:n_select_sample]   ← Keep top 5
   │      │    queue = selected
   │      │
   │      │  Depth 1:
   │      │    queue = [top 5 nodes from depth 0]
   │      │    for each of 5 nodes:
   │      │        proposals = propose(node.state)       ← 5 proposals each
   │      │        [next_queue has ~25 nodes created]
   │      │    evaluate_state() for each of 25 children
   │      │    sort next_queue by value (descending)     ← SORT ALL 25 TOGETHER
   │      │    selected = next_queue[:n_select_sample]   ← Keep top 5 from 25
   │      │    queue = selected
   │      │
   │      │  [Repeat for Depth 2, 3, 4, 5...]
   │      │
   │      │  KEY INSIGHT:
   │      │  • Sorting happens GLOBALLY (all proposals together)
   │      │  • NOT per-parent, so best proposals from any parent advance
   │      │  • Beam width n_select_sample=5 ensures manageable exploration
   │      │  • If solution found → continues until depth 3, then stops
   │      │
   │      │  Dead-End Memory Integration:
   │      │    For each child in next_queue:
   │      │        IF is_potential_dead_end(child.state):
   │      │            skip this child (don't add to queue)
   │      │            stats['deadend_memory_skipped'] += 1
   │      │
   │      └─ Output: (solutions: list[str], root: TreeNode)
   │         solutions = [path_to_24_node_1, path_to_24_node_2, ...]
   │
   │  4️⃣  export_tree_to_json(filename)
   │      ├─ Serializes entire search tree to JSON
   │      ├─ Includes: all nodes, edges, evaluations, statistics
   │      └─ Used for: analysis, debugging, reporting


================================================================================
3. ALGORITHM FLOW: FROM INPUT TO SOLUTION
================================================================================

INPUT: [1, 5, 9, 13]
TARGET: 24

STEP-BY-STEP EXECUTION:
═════════════════════

┌─ INITIALIZATION
│  └─ Game24TreeOfThoughts(temperature=0.7, n_select_sample=5, ...)
│     • Create root node with state=[1, 5, 9, 13]
│     • Create empty trees for nodes and solutions
│     • Initialize DeadEndMemory, SafeAgentSandbox

├─ DEPTH 0 (Generate first-level proposals)
│  │
│  ├─ LLM PROPOSAL PHASE (call propose)
│  │  ├─ Prompt: "Given [1, 5, 9, 13], what operations reach 24?"
│  │  ├─ LLM Response (example):
│  │  │   - Subtract 9 from 13 → [4, 1, 5]
│  │  │   - Add 1 and 5 → [6, 9, 13]
│  │  │   - ... (more proposals)
│  │  │
│  │  ├─ Sandbox Execution (for each proposal):
│  │  │   Code: "res = 13 - 9; new_numbers = [res] + [1, 5]"
│  │  │   Execute safely → new_state=[4, 1, 5]
│  │  │
│  │  └─ Result: 5 child nodes (e.g., IDs: 1, 2, 3, 4, 5)
│  │
│  ├─ EVALUATION PHASE (call evaluate_state for each child)
│  │  ├─ Node 1: [4, 1, 5]
│  │  │   • NOT single number, NOT two numbers
│  │  │   • Call VALUE_PROMPT_CODEACT 3 times
│  │  │   • Responses: "sure", "sure", "sure"
│  │  │   • Votes: 3×sure → raw_score=1.0 → boosted_score=1.0 ✓
│  │  │
│  │  ├─ Node 2: [6, 9, 13]
│  │  │   • Responses: "likely", "likely", "sure"
│  │  │   • Votes: 2×likely + 1×sure → 0.6+0.6+1.0=2.2 → score=0.733
│  │  │
│  │  ├─ Node 3: [14, 1, 5]
│  │  │   • Responses: "likely", "likely", "likely"
│  │  │   • Votes: 3×likely → score=0.6
│  │  │
│  │  └─ [Similar for Nodes 4, 5...]
│  │
│  ├─ SELECTION PHASE (beam search)
│  │  ├─ Sort by value DESCENDING:
│  │  │   1. Node 1: value=1.0   ← HIGHEST
│  │  │   2. Node 2: value=0.733
│  │  │   3. Node 3: value=0.600
│  │  │   4. Node 4: value=0.567
│  │  │   5. Node 5: value=0.533
│  │  │
│  │  └─ Select top-5: queue = [Node1, Node2, Node3, Node4, Node5]
│  │     (In this case, all 5 qualified!)
│  │
│  └─ END DEPTH 0: queue contains 5 nodes, ready for depth 1

├─ DEPTH 1 (Expand each node in queue)
│  │
│  ├─ LOOP: for each node in queue (5 iterations)
│  │  │
│  │  ├─ ITERATION 1: Node 1 = [4, 1, 5]
│  │  │  ├─ LLM proposes 5 ways to combine: [6, 4], [5, 5], [20, 1], etc.
│  │  │  ├─ Create 5 child nodes
│  │  │  └─ next_queue now has 5 nodes
│  │  │
│  │  ├─ ITERATION 2: Node 2 = [6, 9, 13]
│  │  │  ├─ LLM proposes 5 ways
│  │  │  └─ next_queue now has 10 nodes
│  │  │
│  │  ├─ ITERATION 3: Node 3 = [14, 1, 5]
│  │  │  └─ next_queue now has 15 nodes
│  │  │
│  │  ├─ ITERATION 4: Node 4
│  │  │  └─ next_queue now has 20 nodes
│  │  │
│  │  └─ ITERATION 5: Node 5
│  │     └─ next_queue now has ~25 nodes (minus deduplication)
│  │
│  ├─ EVALUATE all 25 nodes
│  │  └─ Each node gets a score
│  │
│  ├─ SORT ALL 25 NODES TOGETHER by value (descending)
│  │  ┌─────────────────────────────────────────┐
│  │  │ CRITICAL: GLOBAL SORT ACROSS ALL NODES  │
│  │  │ Best proposals from ANY parent rise up  │
│  │  │ Not per-parent, but globally            │
│  │  └─────────────────────────────────────────┘
│  │
│  │  Example sorting:
│  │    1. [6, 4] (from Node1) value=1.0 ✓ Can reach 24!
│  │    2. [5, 5] (from Node1) value=0.867
│  │    3. [...] (from Node2) value=0.733
│  │    ...
│  │    25. [...] value=0.001
│  │
│  ├─ SELECT top 5: queue = [best 5 from 25 nodes]
│  │  └─ Example: queue = [[6,4], [5,5], [...Node2's best...], ...]
│  │
│  └─ END DEPTH 1: queue contains 5 best nodes from 25 proposals

├─ DEPTH 2 (Expand top 5 from depth 1)
│  │
│  ├─ SPECIAL CASE: [6, 4] is a 2-number state
│  │  ├─ Can reach 24? Check all operations:
│  │  │   6+4=10, 6-4=2, 6*4=24 ✓✓✓ FOUND!
│  │  │
│  │  ├─ Create child node: [24]
│  │  ├─ Mark as SOLUTION
│  │  │
│  │  └─ Continue exploring (don't stop immediately)
│  │
│  ├─
│  │  └─ next_queue has ~5 new nodes (+ the [24] solution)
│  │
│  ├─ EVALUATE all nodes in next_queue
│  │  └─ [24] automatically scores 1.0
      |_ final verification
│  │
│  ├─ SORT all nodes by value
│  │
│  ├─ SELECT top 5 again
│  │
│  └─ END DEPTH 2: solution [24] is now in the tree!

├─ DEPTH 3
│  └─ Final step and one number remains:
│     • Solution found (continue to depth 3)
│     • OR no more viable nodes

└─ RETURN
   ├─ solutions = [Node with state=[24]] or none founnd
   ├─ root = original root node (fully populated tree)
   └─ Export tree to JSON with all metadata
